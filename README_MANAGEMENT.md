# 🤖 Policy RAG Assistant — สรุปสำหรับผู้บริหาร (v2.0)

![Status](https://img.shields.io/badge/Status-Live%20%26%20Tested-2ECC71?style=for-the-badge)
![Data](https://img.shields.io/badge/Data-On--Prem%20Only-3498DB?style=for-the-badge)
![Review](https://img.shields.io/badge/AI%20Drafts-Require%20Human%20Approval-E67E22?style=for-the-badge)

ผู้ช่วย AI ที่ตอบคำถามเรื่องนโยบาย/ระเบียบปฏิบัติของ **บริษัท ออริจิ้น โกลบอล เอ็มไพร์ จำกัด (มหาชน)** ให้พนักงานแทนการเปิดไฟล์เอกสารทีละฉบับ พร้อมความสามารถช่วยร่างนโยบายใหม่เป็นจุดเริ่มต้นให้ทีมไปตรวจสอบต่อ — ทุกคำตอบยึดตามเอกสารจริงขององค์กรเท่านั้น ไม่มีการตอบมั่ว

---

## 🆕 อัปเดตล่าสุด — v2.0

**Status: Shipped** — ผ่านการทดสอบ end-to-end ครบ 6/6 เคส พร้อมใช้งาน

- **ป้องกันระบบสะดุดตอนใช้งานหนัก (Auto Model Fallback):** เมื่อโมเดล AI หลักถูกใช้จนครบโควตาต่อเนื่อง (เช่น ช่วงพีคที่มีคนถามพร้อมกันเยอะ) ระบบจะสลับไปใช้โมเดลสำรองให้อัตโนมัติ แทนที่จะหยุดตอบ — ลดความเสี่ยงเรื่อง downtime โดยไม่ต้องมีคนเข้ามาแก้ไขหน้างาน (ฟีเจอร์นี้ปิดอยู่โดยดีฟอลต์ รอทีมตัดสินใจเลือกโมเดลสำรองที่จะใช้ก่อนเปิด — ดู "สิ่งที่ต้องตัดสินใจ" ด้านล่าง)
- **คุยต่อเรื่องร่างเอกสารในแชทได้:** หลังพนักงานสร้างร่างนโยบายในโหมดร่างเอกสารแล้ว สามารถกลับไปถามในแชทปกติต่อได้เลย (เช่น "อธิบายข้อ 3 ในร่างให้หน่อย") ช่วยลดรอบการทำงานซ้ำ — ระบบติดป้ายกำกับชัดเจนทุกครั้งว่าเนื้อหานี้ยังไม่ผ่านการอนุมัติ และจำกัดให้เห็นเฉพาะเซสชันเดียวกันเท่านั้น ป้องกันความสับสนกับนโยบายที่ใช้งานจริง

## 🕒 อัปเดตก่อนหน้า

### v1.1 — เพิ่มขั้นตอนถามข้อมูลก่อนร่างเอกสาร
**Status: Shipped**
แก้จุดเสี่ยงที่พบระหว่างทดสอบ: เดิมระบบร่างเอกสารทันทีโดยไม่ถามข้อมูลเพิ่ม เสี่ยงต่อการ "เดา" ข้อมูลเฉพาะองค์กรที่ไม่มีอยู่ในเอกสารเดิม (เช่น หัวข้อ PDPA ที่ต้องรู้รายละเอียดการเก็บข้อมูลส่วนบุคคลของบริษัทเอง) ตอนนี้ระบบจะถามคำถามเฉพาะจุดที่ข้อมูลขาดก่อนร่างเสมอ ตอบไม่ครบก็ได้ ระบบจะทำเครื่องหมายจุดที่ยังขาดไว้ในร่างแทนการเดาเอง

### v1.0 — โหมดร่างนโยบายใหม่ + ตรวจสอบตัวเองอัตโนมัติ
**Status: Shipped**
เพิ่มความสามารถให้ระบบ "ร่าง" นโยบายใหม่ที่ยังไม่มีอยู่ (ไม่ใช่แค่ค้นหาของเดิม) พร้อมให้ AI วิจารณ์ร่างของตัวเองทันทีเทียบกับนโยบายที่มีอยู่จริง แบ่งระดับความเสี่ยงชัดเจน (วิกฤต / ควรตรวจสอบ / จุดเล็กน้อย / สรุปภาพรวม) — **ทุกร่างต้องผ่านการอนุมัติจากมนุษย์ก่อนใช้งานจริงเสมอ ไม่มีข้อยกเว้น**

## 💼 คุณค่าทางธุรกิจ

- **ลดเวลาค้นหานโยบาย** — พนักงานถามด้วยภาษาพูดปกติแทนการเปิดไฟล์ทีละฉบับ พร้อมอ้างอิงรหัสเอกสาร/หัวข้อกลับไปตรวจสอบต้นฉบับได้ทุกคำตอบ
- **จุดเริ่มต้นสำหรับร่างนโยบายใหม่** — ลดเวลาตั้งต้นของทีมที่ต้องเขียนนโยบายใหม่ ระบบช่วยแต่งโครงร่างที่สอดคล้องกับรูปแบบเดิมขององค์กรให้ก่อน ทีมไปเน้นตรวจสอบและปรับแก้ต่อ
- **ต้นทุนควบคุมได้** — ไม่มีค่าใช้จ่ายรายเดือนของ SaaS ภายนอก ต้นทุนหลักคือค่าเรียกใช้ Gemini API ตามปริมาณการใช้งานจริงเท่านั้น

## 🔒 ความปลอดภัยและความเสี่ยงที่ควบคุมไว้แล้ว

| ความเสี่ยง | มาตรการที่มีอยู่ |
|---|---|
| AI ตอบข้อมูลผิด/มั่วในโหมดถาม-ตอบ | บังคับให้ตอบจากเอกสารจริงเท่านั้น ("กฎเหล็ก") — ไม่เคยถูกปลดตลอดการพัฒนา |
| ร่างเอกสารที่ AI แต่งถูกนำไปใช้จริงโดยไม่ตรวจสอบ | ทุกหน้าจอมีคำเตือนชัดเจน + AI วิจารณ์ตัวเองก่อนส่งให้คน + จุดที่ AI ไม่มั่นใจถูกทำเครื่องหมายไว้ให้เห็นชัด |
| ร่างเอกสารปนกับนโยบายจริงในแชท | จำกัดให้เห็นเฉพาะเซสชันเดียวกัน ไม่บันทึกลงฐานข้อมูลถาวร ติดป้ายกำกับทุกจุด |
| ข้อมูลบริษัทรั่วไหลออกนอกองค์กร | เอกสารและการประมวลผลอยู่บนเครื่องภายในองค์กรทั้งหมด มีแค่การเรียก Gemini API เพื่อสรุปคำตอบเท่านั้นที่ออกนอกเครื่อง |
| ระบบหยุดตอบตอนใช้งานหนัก | มีกลไกสลับโมเดลสำรองอัตโนมัติพร้อมใช้แล้ว (v2.0) รอทีมเปิดใช้งาน |

## 🗳️ สิ่งที่ต้องตัดสินใจจากทีมบริหาร/IT

1. **เลือกโมเดลสำรอง (fallback model)** — ฟีเจอร์ auto-fallback พร้อมใช้แล้วแต่ปิดอยู่โดยดีฟอลต์ ต้องเลือกโมเดลสำรอง (เช่น Gemma 4) และทดสอบคุณภาพก่อนเปิดใช้งานจริง
2. **งบประมาณ Gemini API** — ต้นทุนแปรผันตามปริมาณการใช้งาน หากขยายให้พนักงานใช้วงกว้างขึ้นควรประเมินงบประมาณล่วงหน้า
3. **พื้นที่จัดเก็บถ้าจะขยายไปเครื่องอื่น** — ระบบต้องการพื้นที่ดิสก์ ~15GB ต่อเครื่องที่ติดตั้ง (โมเดล AI + ไลบรารี) ควรวางแผนล่วงหน้าหากจะ deploy เพิ่ม
