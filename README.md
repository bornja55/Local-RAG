# 24CS Policy RAG Assistant

ผู้ช่วยตอบคำถามเรื่องนโยบายและระเบียบปฏิบัติของบริษัท ทเวนตี้ โฟร์ คอน แอนด์ ซัพพลาย จำกัด (มหาชน) — พนักงานพิมพ์คำถามเป็นภาษาไทยธรรมดา แล้วระบบค้นเอกสารที่เกี่ยวข้องพร้อมอ้างอิงรหัสเอกสารและหัวข้อให้อัตโนมัติ ไม่ต้องเปิดหาไฟล์เองทีละฉบับ

## เริ่มใช้งาน

**สิ่งที่ต้องมีก่อน:** โฟลเดอร์ `models/` (โมเดล embedding + reranker), โฟลเดอร์เอกสาร (`Policies/`, `Procedures/`, `Manuals/`, `Forms/`) และ Gemini API key — ไฟล์เหล่านี้ไม่ได้อยู่ใน git (ดูเหตุผลด้านล่าง) ต้องคัดลอกมาไว้ในโฟลเดอร์โปรเจกต์เอง

1. คัดลอก `.env.example` เป็น `.env` แล้วใส่ API key จริงของคุณ
2. ติดตั้ง dependencies: `pip install -r requirements.txt`
3. รัน `run_app.bat`
4. รอครั้งแรกประมาณ 4 นาที (โหลดโมเดล) ครั้งต่อไปจะเร็วขึ้นมากเพราะโมเดลถูกโหลดค้างไว้เบื้องหลัง

ถ้าต้องการปิดระบบให้สนิท (บังคับให้โหลดโมเดลใหม่ในรอบถัดไป) รัน `stop_worker.bat`

## โครงสร้างระบบ

แอปแบ่งเป็น 2 โปรเซสแยกกัน คุยกันผ่าน local HTTP:

- **`app.py`** — หน้าเว็บ Streamlit ที่ผู้ใช้เห็น เบามาก ไม่มีการประมวลผล AI ใดๆ อยู่ในตัวเอง
- **`rag_worker.py`** — โปรเซสเบื้องหลังที่ทำงานหนักทั้งหมด (ค้นเอกสาร + เรียก Gemini) แยกจาก Streamlit โดยสิ้นเชิง

เหตุผลที่แยก: ตอน dev พบว่าถ้าใส่โมเดล AI ไว้ในโปรเซสเดียวกับ Streamlit บน Windows จะทำให้โปรแกรมค้าง/ปิดตัวเองแบบสุ่มหลังใช้งานไปสักพัก การแยกโปรเซสตัดปัญหานี้และเป็นผลพลอยได้คือรีสตาร์ทหน้าเว็บได้เร็วขึ้นด้วย (ไม่ต้องโหลดโมเดลใหม่ทุกครั้ง)

ไฟล์อื่นๆ ในโปรเจกต์:
- `build_index.py` — สร้าง/rebuild ฐานข้อมูลค้นหา (`storage/`) จากเอกสารในโฟลเดอร์ `Policies/Procedures/Manuals/Forms` — ต้องรันใหม่ทุกครั้งที่มีเอกสารเพิ่ม
- `extract_forms.py`, `convert_forms_to_txt.py`, `dump_raw_forms.py` — เครื่องมือแปลงไฟล์แบบฟอร์มดิบให้เป็น Markdown ก่อนเข้าระบบ
- `test_rag_pipeline.py` — ทดสอบว่าระบบทำงานถูกต้องแบบ end-to-end (ไม่ต้องเปิด Streamlit ก่อน)

## สิ่งที่ไม่ได้เก็บใน git (ตั้งใจ)

| ไม่เก็บ | เหตุผล |
|---|---|
| `.env` | มี API key จริง |
| `models/` | ไฟล์โมเดลขนาดใหญ่เกินกว่า git จะจัดการได้ดี |
| `storage/` | ฐานข้อมูลค้นหาที่ build ได้ใหม่จาก `build_index.py` |
| `Policies/`, `Procedures/`, `Manuals/`, `Forms/`, `Forms_Raw/` | เอกสารภายในบริษัท ไม่ควรอยู่ใน git |

## แก้ปัญหาเบื้องต้น

- **หน้าเว็บค้างที่ "กำลังเริ่ม RAG worker process..." นานเกินไป** — เช็คไฟล์ `rag_worker.log` ในโฟลเดอร์โปรเจกต์ จะบอกสาเหตุ (เช่น หา `.env`/โมเดลไม่เจอ)
- **แก้เอกสารแล้วคำตอบไม่อัปเดต** — ต้องรัน `build_index.py` ใหม่ แล้ว `stop_worker.bat` ก่อนเปิดแอปอีกครั้ง (worker ไม่รู้ว่าเอกสารเปลี่ยนจนกว่าจะรีสตาร์ท)
- **อยากรู้ว่า worker ยังทำงานอยู่ไหม** — เปิด Task Manager หา process `python.exe` ที่ไม่ได้ผูกกับหน้าต่าง terminal ไหนเลย
