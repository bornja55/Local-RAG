Fallback logic (llm_fallback) เป็น deep module ที่ดีอยู่แล้ว แต่ติดอยู่ในไฟล์ที่ test ไม่ได้

ไฟล์: rag_worker.py:380-479
ปัญหา
_is_quota_error / _is_fallback_worthy_error / _build_llm / _complete_with_fallback ออกแบบมาดีแล้ว (interface เล็ก: complete_with_fallback(model, fallbacks, prompt) → (text, error), ซ่อน retry/backoff/classification ทั้งหมดไว้ข้างใน) แต่เพราะอยู่ปนกับส่วนที่ต้องโหลด ML model ทั้งไฟล์ ทำให้เขียน unit test แบบ mock exception เพื่อเช็คว่า "timeout ควร trigger fallback" ไม่ได้จริง ๆ (ต้อง boot worker ทั้งตัวถึงจะเทสได้) — นี่คือสาเหตุจริงที่ bug "timeout ไม่ trigger fallback" (แก้ไปแล้วรอบที่แล้ว) ไม่มี test จับได้ตั้งแต่แรก
ข้อเสนอ
ย้าย 4 ฟังก์ชันนี้ไป llm_fallback.py แบบไม่มี import จาก llama_index/torch ที่ top-level (import GoogleGenAI แบบ lazy ข้างในฟังก์ชันเหมือนเดิมได้) แล้วเพิ่ม test_llm_fallback.py แบบ pure unit test (mock exception object ล้วน ๆ ไม่ต้องมี API key หรือโหลดโมเดลเลย) ครอบคลุมเคสที่ scrutinize เจอไปแล้ว: quota error → fallback, timeout → fallback, error อื่น ๆ ที่ไม่เข้าเงื่อนไข → ไม่ fallback
